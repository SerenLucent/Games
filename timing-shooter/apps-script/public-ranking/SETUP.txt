Games Public Timing Shooter Rankings - Stage Boards

For the existing ranking project:
1. Replace Code.gs in the public ranking Apps Script project.
   Do not replace the multiplayer project or the AST native score project.
2. Keep the existing GITHUB_TOKEN, GITHUB_OWNER, GITHUB_REPO,
   GITHUB_BRANCH and SCORE_PATH script properties unchanged.
3. Deploy a new version of the existing Web app. Keep the same /exec URL.
4. Run migrateStageRankings once. It converts the latest live JSON to schema v2,
   preserving all old records as stage1 and creating an empty stage2 board.
5. Keep the existing resetWeeklyRankings trigger. It now handles every stage.
   New installations can run installWeeklyResetTrigger once.

Each stage has its own weekly and all-time TOP 10 RUNS, not one shared ranking.
Weekly periods start Monday 00:00 Asia/Seoul; all-time records are retained.
Missing stageId from legacy clients is treated as stage1.
The new client blocks stage2 registration against an old ranking server.

Do not overwrite live rankings.json with an old snapshot or empty seed.
The included rankings.stage-v2.json is a prepared example/snapshot, not a
replacement for data that players may have changed since it was prepared.
The migration function reads and converts the latest GitHub SHA under a lock.

No GitHub token belongs in the browser or repository. Configure it only in
Apps Script properties, with Contents read/write access to the Games repo.
No APP_KEY is needed for the public leaderboard. Client scores are not fully
trusted; basic validation does not prevent deliberate cheating or spam.

For a new project, default properties are:
GITHUB_OWNER = SerenLucent
GITHUB_REPO = Games
GITHUB_BRANCH = main
SCORE_PATH = timing-shooter/rankings.json

See README.md for storage and request details.
